# 모바일 오디오 처리와 웨어러블 연동

[← 음향 센싱 개요](cardio.md) · [포트폴리오](../README.md)

**신호처리 알고리즘을 모바일의 수집·기록·재생 경로에 적용하고, 기기 상태와 워치 피드백을 연결했습니다.** 아래에서는 오디오 처리 루프, 상태 제어와 데이터 전달의 구현 경험을 설명합니다.

`MATLAB` `Audio DSP` `Kotlin` `IMU` `Wear OS` `Coroutines`

## 오프라인 분석에서 모바일 처리로

MATLAB에서 파형과 spectrum을 분석하고 필터링 함수를 구현했습니다. 단일 마이크 신호처리와 듀얼 마이크 입력을 다루며, 분석 환경과 앱의 오디오 입출력 조건을 구분했습니다.

모바일에서는 오디오 입력을 수집하고 처리 결과를 출력하는 반복 경로를 구성했습니다. 원본 기록은 필터 처리 전에 분기해, 처리 전 데이터와 처리 결과를 각각 확인할 수 있도록 했습니다.

## 오디오 루프와 제어 경로 분리

FFT 계산과 입출력에 사용하는 배열을 재사용했습니다. 사용자 설정이나 상태 제어 요청은 오디오 샘플 처리와 분리해 전달하고, 처리 루프에서 반영했습니다.

듀얼 마이크 경로에서는 primary와 reference 입력을 분리하고, 필터 사용 여부가 바뀌어도 입력 장치를 다시 구성하지 않도록 했습니다. 출력 단계에서는 처리 결과와 gain 변화를 적용했습니다.

## 움직임 판정과 출력 정책

가속도와 각속도 데이터를 이용해 기기의 움직임 상태를 판정했습니다. 상태 판정과 오디오 출력 정책을 나누어 구현해, 판정 기준과 출력 동작을 각각 조정할 수 있도록 했습니다.

오디오 출력이 바뀔 때에는 gain ramp를 사용했습니다. 신호처리 경로에 모든 제어를 넣는 대신, 기기 상태를 전달받아 출력에 반영하는 구조로 구성했습니다.

## 기록과 워치 피드백의 전달 방식

수집 데이터를 저장하는 기록 경로와 사용자에게 전달하는 실시간 피드백 경로를 구분했습니다. 오디오의 크기 정보를 워치 출력에 맞게 변환하고, 별도의 coroutine에서 전송했습니다.

워치 피드백은 최신 프레임을 우선하도록 구성했습니다. 전송이 밀리면 오래된 피드백을 계속 쌓아두지 않고, 재연결 때에도 남아 있는 오래된 프레임을 정리했습니다.

## 실물 제작과 시스템 연결

Fusion 모델링과 Bambu Lab 출력·조립으로 스마트폰 수집 액세서리를 제작했습니다. 물리적 입력 구조, 신호 분석, 앱의 오디오 출력과 워치 전송을 함께 구현했습니다.
